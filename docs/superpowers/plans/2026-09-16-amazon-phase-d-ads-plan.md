# Amazon Phase D — Amazon Ads Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect the approved Amazon Ads API, synchronize campaign-level and product-attributable advertising metrics for all available European profiles, and include Ads in consolidated/product profitability without arbitrary allocation.

**Architecture:** Amazon Ads has an authorization lifecycle separate from SP-API. Admin starts OAuth in the ZENVIA app; the Edge Function callback validates a short-lived state and stores the Ads refresh token server-side in Supabase Vault. A reporting adapter normalizes either the 2026 Unified Reporting API when the account is entitled or the current Sponsored Ads reporting API as a temporary compatibility provider, while preserving a single internal schema.

**Tech Stack:** Amazon Ads API EU, Login with Amazon OAuth 2.0, Supabase Edge Functions/Postgres/Vault, existing Amazon job queue, React/TypeScript, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-16-amazon-analytics-design.md`

## Global Constraints

- Amazon Ads access requires Amazon approval; implementation must show `Pendiente de aprobación/configuración` cleanly until credentials/API entitlement exist.
- Browser never receives client secret, refresh token, access token, or Vault contents.
- Direct advertiser authorization is separate from SP-API and uses OAuth 2.0/LWA.
- EU Ads base endpoint is server-side only.
- Store both campaign grain and product-attributable grain; never sum both grains together for total spend.
- Consolidated Ads spend uses `scope_type='campaign'` as the source of truth.
- Product profitability uses only `scope_type='product'` rows that Amazon itself relates to ASIN/SKU.
- Any campaign spend not attributable to product rows remains `unallocated_ad_spend`; it affects total Amazon profit but is not distributed across products.
- Ads attribution can change after the day of click/sale, so recent days must be re-requested.
- ACOS/TACOS/ROAS return NULL when denominator is zero.
- The Sponsored Ads legacy reporting path is a compatibility fallback only because Amazon announced retirement of older sponsored-ads reporting in favor of unified reporting by 31/12/2026; keep provider selection behind one adapter.

### Task 6: Incorporate Ads into profitability RPCs

**Files:**
- Create: `supabase/migrations/20260916173100_amazon_profitability_with_ads.sql`
- Modify: `src/services/amazonAnalytics.ts`
- Create: `scripts/amazon-ads-profitability.test.mjs`

**Interfaces:**

- Product rows return only attributable product spend and product-level ACOS/TACOS; they do not receive unallocated spend.

- [ ] **Step 1: Write failing SQL contract test**

Assert total Ads CTE filters `scope_type='campaign'`; product Ads CTE filters `scope_type='product'`; total and product grains are never union-summed as one spend source.

Assert formulas include `NULLIF` denominators.

- [ ] **Step 2: Implement consolidated Ads totals**

For filtered dates/marketplace, sum campaign-grain `spend_eur` and `attributed_sales_eur`.

Final total:

```text
amazon_profit = net_sales_ex_vat
              - refunds_ex_vat
              - non_fba_amazon_fees
              - fba_costs
              - ad_spend
              - cogs
```

`profit_margin = amazon_profit / NULLIF(net_sales_ex_vat,0)`.

`ACOS = ad_spend / NULLIF(attributed_ad_sales,0)`.

`TACOS = ad_spend / NULLIF(gross_sales,0)`.

`ROAS = attributed_ad_sales / NULLIF(ad_spend,0)`.

- [ ] **Step 3: Implement product Ads allocation**

Join product-grain Ads on marketplace + ASIN/SKU/date as supported by normalized report. Never spread campaign-level residual across products.

Compute:

```text
unallocated_ad_spend = total_campaign_spend - sum(product_attributable_spend)
```

Clamp only tiny rounding noise around zero; if the difference is materially negative, flag `ads_allocation_warning` rather than forcing zero because it indicates incompatible grains/report metrics.

- [ ] **Step 4: Define completeness**

`profit_complete` is true only when required SP-API and Ads sources for the scope are synchronized and COGS/FX completeness meets the chosen rule. Return separate flags (`ads_complete`, `cogs_complete`, `fx_complete`) so UI can explain why not.
