# Configuration Center Phase 2 — General, Sales, and Clients Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move company identity, sales defaults, invoice behavior, and client defaults into the Configuration Center without changing existing invoice history.

**Architecture:** Existing structured company/tax/series tables remain canonical. Modular sales/client settings provide defaults and display behavior. Both application code and PostgreSQL due-date behavior read the same effective workspace setting with a 30-day fallback.

**Tech Stack:** React, TypeScript, Supabase/PostgreSQL triggers, jsPDF invoice rendering, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-21-configuration-center-design.md`

## Global Constraints

- Existing issued invoices must not be recalculated or rewritten by changing defaults.
- Existing client-specific payment terms override the global setting.
- Existing explicit invoice values override defaults.
- Business identity and branding continue to use `business_settings` and `company_branding`.
- Tax registrations and invoice series continue to use their existing tables.
- All global writes require admin authorization.

## Review Focus

- Changing default due days affects a newly created draft and database fallback consistently.
- An issued historical invoice keeps its original due date after a setting change.
- A client with 60-day terms still receives 60 days when global default is 30.
- Hiding IBAN/payment method changes PDF presentation but not stored fiscal snapshots.
- A normal user can consume sales settings but cannot change them.

- [ ] **Step 4: Replace the PostgreSQL literal with a workspace setting lookup**

Create:

```sql
create or replace function private.sales_default_due_days(p_owner uuid)
returns integer
language sql
stable
security invoker
set search_path = ''
as $$
  select least(365, greatest(0,
    coalesce((s.config #>> '{sales,defaultDueDays}')::integer, 30)
  ))
  from (select p_owner as owner_id) o
  left join public.app_settings s on s.owner_id = o.owner_id
$$;
```

Ensure malformed JSON text cannot raise a cast exception: use a guarded numeric expression/regex before casting.

Update the trigger to use the row owner/workspace owner and fallback 30.
