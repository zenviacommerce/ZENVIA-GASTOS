# Configuration Center Phase 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the secure, typed settings foundation, isolated development environment, Configuración navigation shell, and per-user preferences.

**Architecture:** Supabase provides workspace-owned settings/rule tables protected by RLS. TypeScript owns schema normalization and defaults. A React provider caches effective settings and preferences so feature modules consume one stable API.

**Tech Stack:** React 19, TypeScript 5.8, Supabase/PostgreSQL/RLS, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-21-configuration-center-design.md`

## Global Constraints

- Work only on `feature/configuration-center`.
- Use a Supabase development branch, not production, for schema/data changes.
- Obtain explicit cost confirmation before creating that branch.
- Do not expose integration secrets.
- RLS must enforce authorization independently of UI visibility.
- Settings parsing must never make app startup fatal.

## Review Focus

- Corrupt nested settings fall back per-property without discarding valid siblings.
- User preferences cannot be read or written for another user.
- Normal users can read effective global settings required by their modules but cannot mutate them.
- Theme preference `system` works without throwing when `matchMedia` is unavailable.
- Configuración remains reachable even if a noncritical settings query fails, with defaults and a visible warning.

- [ ] **Step 3: Create the migration**

Define:

```sql
create table public.app_settings (
  owner_id uuid primary key references auth.users(id) on delete cascade default private.app_workspace_owner_id(),
  schema_version integer not null default 1 check (schema_version >= 1),
  config jsonb not null default '{}'::jsonb check (jsonb_typeof(config) = 'object'),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.user_preferences (
  user_id uuid not null references auth.users(id) on delete cascade,
  owner_id uuid not null references auth.users(id) on delete cascade default private.app_workspace_owner_id(),
  schema_version integer not null default 1 check (schema_version >= 1),
  preferences jsonb not null default '{}'::jsonb check (jsonb_typeof(preferences) = 'object'),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (user_id, owner_id)
);
```

Add `entity_alias_rules`, `shipping_rules`, and `automation_rules` with workspace ownership, active flags, priorities where applicable, unique constraints that prevent duplicate active identity keys, and indexes on `owner_id`, `normalized_alias`, `priority`, and `rule_key`.

- [ ] **Step 4: Add least-privilege grants and RLS**

Use policies equivalent to:

```sql
create policy app_settings_workspace_select
on public.app_settings for select to authenticated
using (owner_id = (select private.app_workspace_owner_id()) and (select private.app_is_active()));

create policy app_settings_admin_insert
on public.app_settings for insert to authenticated
with check (owner_id = (select private.app_workspace_owner_id()) and (select private.app_is_admin()));

create policy app_settings_admin_update
on public.app_settings for update to authenticated
using (owner_id = (select private.app_workspace_owner_id()) and (select private.app_is_admin()))
with check (owner_id = (select private.app_workspace_owner_id()) and (select private.app_is_admin()));
```

For `user_preferences`, require both workspace ownership and `user_id = (select auth.uid())` for select/insert/update/delete.

- [ ] **Step 5: Extend auditing safely**

- [ ] **Step 3: Implement persistence**

Use `supabase.auth.getUser()` to identify the current user for preference writes. For global settings, rely on workspace default/RLS and `maybeSingle()`.

When saving a section:

```ts
const current = await loadRawSettings();
const nextConfig = { ...current.config, [section]: value };
const { error } = await supabase.from('app_settings').upsert({
  owner_id: current.ownerId,
  schema_version: APP_SETTINGS_SCHEMA_VERSION,
  config: nextConfig,
  updated_at: new Date().toISOString(),
}, { onConflict: 'owner_id' });
if (error) throw error;
```
